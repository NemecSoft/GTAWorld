## 数据层（tools/gen_city.py 大改）

- **换数据源**：`100000_full.json` 是超低精度版（每省只剩 4~15 个顶点），省界是硬直线、
  多省交界糊成一团麻点 → 改用**逐省高精度** `https://geo.datav.aliyun.com/areas_v3/bound/{adcode}.json`
  （每省上千个顶点），缓存到 `Temp/prov/`，缓存命中就完全离线。
  `100000_full.json` 只用来枚举 34 个省的 adcode/名字。注意：**不带 `_full` 的那个接口才是省本体轮廓**，
  带 `_full` 的返回的是下属地市（level=district，没有 province 要素）。
- **必须抽稀**：高精度数据不抽会五万级循环，跑不动。抽稀放在 km 坐标下，
  `SIMPLIFY_KM = 20.0`（≈2.7 场景米）。
- **跨省顶点吸附取代坐标量化**：两个省各自 DP 抽稀后保留的顶点不一样（河北留 v7、山西留 v9），
  光按坐标量化对不上共界 → 先把顶点吸附到统一 2 米栅格 (`SNAP_Q = 0.5`)、再建边、最后按边去重。
- 串链 → `catmull_closed` 磨圆 → 3 米重采样 → `MIN_LOOP_M = 60` 滤碎岛（22m 那档会出一堆麻点）。
  最终 **30 圈 / 8751 米 / 3015 段 / 162 个路口**。
- 地标塔立在省界的**最远内点**（pole of inaccessibility），不是数据里的 `center`——
  直辖市/小省的 center 常常正好压在边界公路上，塔会长在路中间。
- 树/楼离路心 ≥12 米（`ROAD_CLEAR`），用 30 条环线建的网格索引加速；生成要带重试封顶
  （小省整个辖区都在路缘内，无上限重试会 SIGTERM）。

## 踩到的坑（重要）

- **GDScript 缩进被编辑工具改坏**：在 `for` 循环体里插几行时 `old_string`/`new_string`
  的 tab 数对不齐，就把循环体拆成两层，报 `Parse Error: Expected statement, found "Indent"`，
  行号还指到后面几行，极易误判。插代码前先数已有行的 tab（本项目 .gd 用 **tab** 缩进）。
- **`edges.values()` 不能直接按 `(a, b)` 拆**：key 是 `(id_a, id_b)`、value 是
  `(格坐标a, 格坐标b)`，只拆 values 会把「某端的格坐标」再拆成两个整数 →
  `TypeError: int object is not subscriptable`。必须 `for (ka, kb), (ga, gb) in edges.items()`。
- **链和边的类型必须同构**：一开始 `chain = [p]` 里存格坐标元组、后面 append 顶点编号，
  混着用会 `int object is not subscriptable`。
- headless 在这台机器上**读不回像素**（`texture_2d_get: t is null`，rendering dummy；
  vulkan/d3d12/opengl3/gl_compatibility 全试过）→ 截图探针必须用 **GUI 版 exe + 真实窗口**：
  `C:\Tools\Godot\Godot_v4.7-stable_win64.exe --path . --script Temp/snap.gd --quit-after 400`。
- PowerShell 只回退出码；跑 python 生成器走 bash，且输出重定向要 `python -u`。

## 相机机位锁定（2026-10-03 · 用户：「不论什么速度，相机要和开始的时候一样，不要拉远」）

### 根因有两个，都修了
1. **三个速度旋钮没关**（`scripts/view.gd` 改默认值）：
   - `distance_speed` 0.9 → **0**（满速后退 0.9 m，机位从 2.9 变 3.8）
   - `distance_brake` 0.75 → **0**（刹车贴脸，同样破坏一致性）
   - `fov_speed` 8.0 → **0**（满速 FOV 70→78，视野张开＝视觉上拉远）
2. **一阶跟随的固有滞后（真凶）**：`position_smoothing=7` 的一阶追随时，
   相机在匀速段会**稳态落后 v/7 米**。满速 10.4 m/s → 滞后 1.49 m，
   实测稳态机位 **4.53 m**（比静止的 3.12 m 远 45%），这就是"车一快相机就飘远"。

### 解法：速度前馈（新增 `speed_lead`）
- 新增 `@export_range(0,1.5,0.05) var speed_lead: float = 1.0`
- `var lead = speed_mps / maxf(position_smoothing, 0.001) * speed_lead`
- `distance_target = zoom_target + distance_speed*sf - distance_brake*bf - lead`
- 把稳态滞后先从目标距离里减掉，机位就与速度无关。
- 纯数学验证（`Temp/lead_sim.gd`，复现跟随方程跑 900 帧）：
  - speed_lead=1：v=0 → 3.1197 m / v=5 → 3.0818 / v=10.4 → 3.0409 / v=20 → 2.9684（偏差 <5%）
  - 不补偿：v=10.4 → **4.5340 m**（拉远 45%）
- 1.0 = 完全补偿（默认）；拖到 0.7 会留一点推背滞后感；0 = 关掉恢复旧行为。

### 实测（真实场景 `Temp/camchk.tscn`）
- 全程 `fov` min=max=**70.00**，波动 0.00 → VERDICT: FOV_LOCKED
- 全程 `dist` **max = 2.9710 m**（前馈前满速 4.53 m），拉远彻底消失
- 全程 dist min=0.66 是**撞墙打转时相机绕到车侧**造成的（车头乱转 + slerp 滞后），
  不是速度问题；探针里强制 linear_speed=1 会撞环道 1 格宽的墙，故数据带碰撞噪声。

## Terrain3D 在 4.7 上可用！旧结论被推翻（重要修正）

- **旧错误结论**：「Terrain3D 4.7 不支持，Terrain3DStorage 注册失败」→ **错的**。
  真实原因 = **同一份 dll 被装了两处**（`addons/terrain_3d/` + `Temp/vendor/x/addons/terrain_3d/`），
  引擎报 `Attempt to register extension class 'Terrain3D', which appears to be already registered`
  → 后续类全注册不上，看起来像"引擎不支持"。
- **解法**：只留 **一份** `.gdextension`。清理 `Temp/vendor/`（含 terrain3d.zip 与 x/），
  `find . -name terrain.gdextension -not -path "./ref/*"` 应只输出 `./addons/terrain_3d/terrain.gdextension`。
- **实锤验证**（`Temp/t3d_probe.gd`，`--script` 模式查 ClassDB）：
  `Terrain3D / Region / Material / Collision / Instancer / Util / TextureAsset` 全部 `exists=true instantiate=true`
  （7/8），只有 `Terrain3DStorage` 的 `can_instantiate=false` —— 它是 Resource 格式类，属正常。
  `physics/3d/physics_engine` = **Jolt Physics**（Terrain3D 1.x 原生支持 Jolt）。
- 装的插件版本 = **Terrain3D v1.0.2**（`compatibility_minimum = 4.4`，自带 `libterrain.windows.{debug,release}.x86_64.dll`）。
  **gdextension 只要 addons 目录里有 .gdextension 就会在启动时加载，跟 editor/plugins 里启没启用无关**
  （启用与否只影响编辑器 UI）。所以"注册失败"永远先从"是不是有两份"找原因。
