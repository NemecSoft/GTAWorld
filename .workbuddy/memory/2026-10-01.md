## 修复：编辑视口 / F5 运行花屏（模型碎成小方块）

现象：Godot 4.7 + AMD Radeon RX 580 2048SP（驱动 31.0.21925.1001，Vulkan 1.3.260, Forward+），
编辑器 3D 视口和 F5 运行画面里所有模型碎成孤立小方块、大面（草地/路面）消失，只剩浅蓝天空。
离线 `--write-movie` 渲染却是正常的。

定位过程（在 `D:\AI\GodotProject\_racing46test` 副本里做，不动原项目）：

1. 排除资源问题：`.godot/imported/` 下 13 个 glb 的 `.scn` 都正常生成，脚本无报错。
2. 排除物理/相机：探针脚本 2 秒后打印 `Sphere=(3.5,0.5,5.0) vel≈0`、`View=(3.5,-0.15,5.0)`
   —— 车没掉下去，相机没飞。所以不是脚本 bug。
3. 复现运行时画面：在副本新建 `scenes/_probe.tscn`（instance main.tscn + 挂自动截图脚本）
   用 `get_viewport().get_texture().get_image().save_png()` 自截图，得到和用户截图一致的碎块图。
4. 变量矩阵（用 PNG 大小当指标，正常 ≈ 350~630KB，花屏 ≈ 16KB）：

   | 设置 | PNG | 结果 |
   |---|---|---|
   | 原样 msaa_3d=2 + SSAO/SSIL/Glow | 16KB | 花屏 |
   | msaa_3d=1（2x MSAA） | 500KB | 正常 |
   | msaa_3d=0 | 480KB | 正常 |
   | 保留 MSAA 但关 SSAO/SSIL/Glow | 360KB | 正常 |
   | gl_compatibility 后端 | 627KB | 正常 |

结论：**MSAA 4x 与屏幕空间后处理（SSAO/SSIL/Glow）在 RX 580 上并存会把几何打散**，
属于 AMD 驱动 + Vulkan Forward+ 的坑（对应 Godot issue #109378 那一类 AMD 驱动 Vulkan bug）。

修复：`project.godot` 一行 `anti_aliasing/quality/msaa_3d=2` → `1`（降到 2x MSAA），
SSAO/SSIL/Glow 全部保留。已在原项目验证通过（PNG 499KB，画面正常）。

副作用：跑 Godot 4.7 会重写 26 个 `*.import`（补 `gltf/texture_map_mode` 等新字段），
git status 会显示这些 M —— 用户打开编辑器也会产生，想清掉用 `git checkout -- '*.import'`。

## 改造：把固定机位换成极品飞车式追尾跟随相机

原来的 `scripts/view.gd` 只做 `position.lerp(target.get_vehicle_position())`（平移跟车），
朝向却是 tscn 里写死的斜俯视 45°，看起来像摆拍机位、不跟车头。

新 `view.gd`（重写）：

- 车头方向取 `vehicle_model.global_transform.basis.z` 并把 y 归零（上坡/翻坑时相机不会跟着翻）
- 相机理想位置 `eye = car_pos + (0, height, 0) - forward * distance`，
  `distance = distance(7.5) + distance_speed(4.0) * speed_factor`，speed 来自 `target.linear_speed`（0~1）
- 朝向由 `eye → look` 构造（`look = car + (0, look_at_height, 0) + forward * look_ahead`，默认车前 6 米）
- 位置 lerp / 朝向 `basis.slerp` 平滑，系数用 `1 - exp(-k*delta)`（帧率无关）
- 速度为 0 时相机贴到车上（同一平面），所以 **后退量只能算一次**：要么算在 eye 里、要么算在
  `camera.position.z` 里，两边都写会双重后退把相机甩到车后上方，两边都不写会贴着车
- 导出参数：distance 7.5 / height 3.4 / look_at_height 1.2 / look_ahead 6 /
  distance_speed 4 / fov 58→68 / position_smoothing 7 / rotation_smoothing 5
- 首次进入直接 snap 到位（`_initialized` 标志），避免开场从旧机位飘过去
- `scenes/main.tscn`：Camera `far = 60.0` → `200.0`（否则赛道尽头被裁掉）

验证（副本 `_racingtest`，探针按住 forward 跑 3.5 秒）：
静止 `behind=-7.5 up=3.4 fov=58`；满速 `behind=-11.55 up=3.44 fov=67.8` ✅

## 微调：追尾相机太远（用户反馈"视角太远了"）

第一版留的 distance 7.5 / height 3.4 / fov 58 实测**偏远**（车在画面里只占很小一块）。
改成（当前值）：

- `distance` 7.5 → **4.5**（车后 4.5 米）
- `height` 3.4 → **2.2**
- `look_at_height` 1.2 → **0.9**（车更靠近画面下缘，视野往前铺）
- `look_ahead` 6.0 → **5.0**
- `distance_speed` 4.0 → **2.0**（满速退到 6.5 米，不再甩太远）
- `fov_base / fov_speed` 58/10 → **70/6**（靠大 FOV 补速度感，而不是靠拉远）

验证（副本 `_racingcam`，按住 forward 跑 3 秒）：
静止 `cam=(3.5,2.05,0.5) car=(0,0,0) fov=70`；满速 `behind≈6.5 fov≈74` ✅

**经验：极品飞车式追尾相机，"拉近 + 大 FOV" 比 "拉远 + 小 FOV" 更有速度感，
而且车在画面里够大才有代入感。** 静止时车约占画面高度 1/6~1/5 比较合适（再近就穿模）。

## 迭代：追尾相机改「滚轮调距离」

用户说还是太远 → 默认再拉近 + 加滚轮控制（`scripts/view.gd`）：

- `distance` 4.5 → **3.2**，`height` 2.2 → **1.9**，`look_at_height` 0.9 → **0.8**
- `distance_speed` 2.0 → **1.5**，`fov_base/fov_speed` 70/6 → **72/6**（静止就够广）
- 新增 `_unhandled_input()` 处理 `MOUSE_BUTTON_WHEEL_UP/DOWN`：
  - `zoom` 变量保持 **-1** 表示「先用 `distance`，滚轮一动就接管当前实际距离」
  - 每格 `wheel_zoom_step = 0.4` 米，夹在 `zoom_min=1.2` ~ `zoom_max=20`
  - 目标距离平滑用 `lerpf(_distance_now, zoom_target + distance_speed*speed, 1-exp(-9*delta))`，
    之前 `distance_smoothing` 导出参数是废的（没用上），现在真正接上了
  - 滚轮事件里 `get_viewport().set_input_as_handled()`

验证（副本 `_racingwheel`，用 `Input.parse_input_event()` 造滚轮事件）：
默认 behind=3.42 / 滚轮拉到底 behind=1.51 / 滚轮推远 behind=10.9 ✅

## Godot 4.7 语法坑（这次踩到）

- `Transform3D.looking_at()` 在 4.7 **不是静态构造函数**了（参数变成 3 个、第 3 个是 bool），
  直接 `Transform3D.looking_at(eye, look, up)` 会报
  `Cannot call non-static function ... on the class "Transform3D" directly`。
  自己手搓基向量：`z_axis = -(look-eye).normalized()`；`x_axis = y_axis.cross(z_axis)`；
  再 `y_axis = z_axis.cross(x_axis)` 正交化（三轴满足 X = Y × Z，相机看向 -Z）。
- **鼠标滚轮的常量叫 `MOUSE_BUTTON_WHEEL_UP` / `MOUSE_BUTTON_WHEEL_DOWN`（带 BUTTON 前缀）**。
  `MOUSE_WHEEL_UP`（Godot 3 写法）会报 `Identifier not declared`，
  `MouseButton.WHEEL_UP` 会报 `Cannot find member in base "MouseButton"` —— 两个都试错了。
- `[System.IO.File]::WriteAllLines($p, $lines)` **本身写的就是 CRLF**，再对内容做一次
  `Replace("\n","\r\n")` 会变成 `\r\r\n`，GDScript 报 `Stray carriage return character in source code`。
  要 CRLF 就 `WriteAllText($p, ($lines -join "`r`n"))`，别两步走。
- 测试滚轮时可以用 `Input.parse_input_event(InputEventMouseButton.new())` 在脚本里造滚轮事件，
  不需要真去滚鼠标；配合 `Input.parse_input_event` 注意 `_unhandled_input` 必须真的收到事件。
- `var v := some_node.global_transform.basis.z` 这种**链式赋值会被判"无法推断类型"**，
  从别的脚本里读属性也一样，必须写成 `var v: Vector3 = ...`、`var f: float = ...` 显式标注。

## 复用要点

- 排障 Godot 渲染问题时，**"自截图探针"（instance 场景 + 定时 `get_viewport().get_texture().get_image()`）
  比抢屏/ddagrab 好用得多**，不打扰用户桌面，且拿到的就是游戏视口真实内容。
- 验证相机跟随时，光看截图不够快，**打印 `(cam - car) · forward`（应为负 = 在车后）和 `up`（应为 height）**
  一行就能定位是"没后退/后退两次/贴着车"；`(-cam.global_basis.z) · forward` 应接近 1（朝车头看）。
- 在 PowerShell 里往 `.gd` 注入调试 `print` 时，双引号字符串里的反引号（`\n`/`\t`）会被 shell 吃掉
  导致 `ParserError: Unexpected token`。改用 Write 工具单独写一个探针 .gd 再 Copy 过去，
  比正则替换安全得多。
- 删除测试产物时 safe-delete 第一次常报 `genie-trash failed`，**同一条命令再跑一遍就成功**，
  不用换工具。
- PNG 文件大小是极好的"画面是否正常"指标，比看图快：纯色/碎块 ≈ 十几 KB，正常场景 ≥ 350KB。
- `Godot --headless --write-movie` 会崩（dummy 后端 `texture_2d_get: Parameter "t" is null`），
  想离线渲染必须不加 `--headless`。
