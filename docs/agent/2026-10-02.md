## Godot 4.7 这次新踩的语法/API 坑

- `SurfaceTool` **没有** `append_with_transform`（也没有 `get_vertex_count`）。
  → 改成手写 `ArrayMesh` + `PackedVector3Array/PackedColorArray/PackedInt32Array`。
- `add_surface_from_arrays(primitive, arrays, blend_shapes, lods, flags)` 签名变了，
  索引要塞进 `arrays[Mesh.ARRAY_INDEX]`（用 `arrays.resize(Mesh.ARRAY_MAX)` 占位）。
- `BoxMesh` **没有** `uv_scale`；`Texture2D` 没有 `wrap_s/wrap_t`（`ClassDB.class_get_integer_constant_list`
  查过，压根没有 `WRAP_*` 常量）→ UV 必须落在 0~1，所以改成**顶点色**画窗格，不依赖贴图平铺。
- 材质属性叫 **`emission`**（不是 3.x/4.0 的 `emissive`），配 `emission_enabled = true`。
- **`AmbientLight3D` 在 4.7 已不存在**（4.4 就删了），环境光要在 `WorldEnvironment` 的环境资源里加。
- `MeshInstance3D` 的 `material` 不可写，要写 `material_override`（4 处都会报 Invalid assignment）。
- `Label3D` 没有 `Base3DBillboard` 枚举（`Identifier not declared`），默认就是 Y 轴公告板。
- `Camera3D` 未入树时 `position = ...` + `look_at()` 会报
  `Node not inside tree. Use look_at_from_position()`，要用 `look_at_from_position(eye, target)`。
- **手写顶点时绕序极易搞反** → 与其纠结，不如全静态几何设 `mat.cull_mode = CULL_DISABLED`
  （双面），一次性绕开「空洞/黑墙」。
- `SceneTree.root` 是 **read-only**，不能 `root = node`，只能 `root.add_child(node)`。
- `ResourceUID` 在 4.7 是**静态类**（不是单例）：`ResourceUID.id_to_text(1784075987)` → `uid://bfjbylf`。
  手编的 `uid://` 字符串会被判 `invalid UID` 警告，**必须用这个 API 生成**。
- 踩过 UID 冲突：`.gd.uid` 文件内容被我原样抄进 `.tscn` 的 ext_resource，
  场景自身 UID 和脚本 UID 撞同一个 → 每次加载都刷 WARNING。修法：给脚本分配新 UID
  （`id_to_text` 生成），`select.gd.uid` 和 `select.tscn` 的 `ext_resource` 一起改，
  再跑一次 `--headless --import` 建 UID 缓存，警告就消失了。
  **注意 `--script` 探针模式下查不到 UID 缓存，所以必然刷 invalid UID 警告——不是 bug，跑 `--import` 就好。**

## 极品飞车街机操控 + 红警2式随机赛道生成（任务 #21/#22/#25/#27）

`scripts/vehicle.gd`（重写）：自研 RayCast 车，`Node3D + RayCast3D + RigidBody3D(Sphere, mass 1000)`。
**关键认知：本项目不是 `VehicleBody3D`**，提示词里的 engine_force/brake/friction 没有同名属性，
映射为 `engine_power / brake_power / lateral_grip`。街机手感靠 **yaw 与 velocity_dir 分离**：
`velocity_dir = lerp(velocity_dir, forward_from_yaw(yaw), 1-exp(-lateral_grip*delta))`，
差值即 `drift_angle`（甩尾角），相机直接读它做横向让位。视觉朝向每帧由 `steer_visual_yaw()` 从 yaw 反推，
不能用 `rotate_y` 累加（会漂）。另有 pitch/roll 重量转移、前轮转角、拖痕看 `slip`。
`scripts/view.gd`：加速拉远 `distance_speed=1.2` / 刹车拉近 `distance_brake=0.9` /
FOV 随速度 `fov_base=68 + fov_speed=8` / 甩尾横移 `drift_offset=2.6`。

`tools/track_generator.gd`（新建，红警2 掩码拼接）：
- 掩码 `PX=1/PZ=2/NX=4/NZ=8`，直道基 10、弯道基 3；**先铺面、再由铺面反推掩码**
  （按中心线推算会漏转角外凸那 1 格，实测 29 条断边）。
- 闭环用**星形多边形 + 曼哈顿 L 形**（随机游走 + BFS 回程实测 120/120 必败：游走会把自己围死）。
- item 编号：0 empty / 1 forest / 2 tents / 3 corner / 4 finish / 5 ramp / 6 straight。
- GridMap **故意不加 material_override**（MeshLibrary 只吃网格内部材质）。

## 诊断：编辑器里「一条横贯画面的树/楼带 + 上下全是天」是什么（city.tscn 行尾注释坑）

现象：跑 `scenes/city.tscn`（地图 2 迷你中国城），3D 视口里只有一条水平色带，
上下全是纯蓝天空，没有车、没有路。这个画面来自 **city.tscn**，不是渲染坏了。

根因链（逐环实测验证）：

1. `scenes/city.tscn` 第 46 行写了 **属性行尾 # 注释**：
   `far = 4000.0          # 世界跨度 2600 米，far=1200 会把远处的楼和地平线剪掉`
2. **Godot 的 .tscn 不认行尾注释**（只有整行以 `#` 开头才算注释）。
   `# …` 被当成属性值的一部分 → 该属性赋值失败 →
   **该节点块之后的解析被静默中断，后面所有 `[node]` 整段丢弃，且不报任何错**。
   最小复现：`fov = 68.0          # 视野` 后面跟一个 instance 节点 →
   `SceneState.get_node_count()` 只有 2，第三个节点消失；
   注释挪到独立一行就恢复 3 个节点。
3. → 场景里根本没有 Vehicle 节点，`View.target = NodePath("../Vehicle")` 解析成 null。
4. → `scripts/view.gd` 的 `_physics_process` 第一句就 return，追尾相机永远不接管，
   相机一直停在 tscn 里写的 `(0,0,8)`，**y=0 贴地朝 -Z 平视**。
5. → 地面与视线共面（看不出地面），966 棵树 + 395 栋楼全长在 y=0，
   于是全压在同一条地平线上 → 就是那条色带；车不在场景里，画面里当然没有车。

修复：`scenes/city.tscn` 第 46 行改成「独立一行注释 + `far = 4000.0`」。
修复后 SceneState 7 个节点、Vehicle 回到树、View.target 解析成功、
相机跑到车后 (542.7, 1.94, -474.1)、脚下射线命中地面。

排查手法（可复用）：写 `tools/scene_report.gd`（`extends SceneTree` + `--script` 跑 headless），
打印 `SceneState.get_node_count()` / 各节点名 / 相机 global pos / View.target / 脚下向下射线。
**坑：在 `_initialize()` 里 add_child 之后节点不算 inside tree，`global_transform` 取不到
（报 `!is_inside_tree()`），必须改到 `_process()` 第 3 帧再 dump。**

## 提速 + 贴身机位（用户：「车速太慢了，视角还是太远了」→ 要参考截图那种贴屁股视角）

根因（这是个真 bug，不是参数没调好）：
1. `scripts/vehicle.gd` 里 `linear_speed` 是 **0~1 的归一化油门量**，却直接被当 m/s 写进刚体：
   `sphere.linear_velocity = velocity_dir * absf(linear_speed)` → 满油门只有 **1 m/s ≈ 3.6 km/h**。
   修法：新增 `max_speed = 40.0`（m/s ≈ 144 km/h），写刚体前乘上去，对外给 `get_speed_mps()`。
   同时 `engine_power` 6.0 → 1.1、`brake_power` 9.0 → 3.5（原来 1 秒就到顶，太突兀）。
2. `scripts/view.gd` 机位拉远了：`distance` 5.0→2.9、`height` 1.55→1.15、
   `look_at_height` 0.75→0.55、`look_ahead` 11→14、`distance_speed` 1.2→0.9、
   `fov_base` 68→70、`fov_speed` 8（不变）、`drift_offset` 2.6→2.2、`zoom_min` 1.2→0.9。
   实测稳态：相机距车 3.84 m、满速 FOV ≈ 78。
3. `scripts/view.gd` 的刹车拉近**原来恒等于 0**（无效代码）：
   `(speed_prev - speed) * 0.7` 用的是归一化速度，每帧只掉 1/60，乘常数永远到不了 1。
   改成 `(Δv/Δt)` 真实减速度 / 60 m/s² 归一化。
4. `scenes/main.tscn` 那块**看不见的碰撞地板** 60×60 → 600×600：
   车速提到 40 m/s 后一冲出赛道就掉进虚空。它是纯碰撞体（没有 mesh），放大不影响任何视觉。

实测（tools/drive_probe.gd，headless 按住 W 跑 4 秒）：
  t=1s 56 km/h → t=2s 93 km/h → t=3s 115 km/h → t=4s 142 km/h（指数趋近，没到顶就撞护栏了）

新增工具 `tools/drive_probe.gd`（extends SceneTree，`--script` 跑 headless，支持 --scene= / --frames=）：
按住前进键跑 N 帧，打印 ls / 真实 m/s / km/h / 车位置 / 相机距车 / fov。
两个必记的坑：
  - SceneTree 的 `_physics_process` 签名是 `(delta) -> bool`，写 `-> void` 直接 Parse Error。
  - 打印车位置要 `get_vehicle_position()`（车模 Container/Model），
    取 Vehicle 节点自己永远停在 tscn 的出生点（车动的是它的子节点）。

## 这轮新踩的坑（已同步进 docs 第 8 节表格 17~22）

- **`@export_range(0,10,0.1) var x: float = 0` 在 4.7 里必须单行**；两行式（下一行再 @export var）
  直接 Parse Error：`Annotation "@export" cannot be used with another "@export" annotation`。
  另外 GDTuner 自带的 bake 正则只认两行式，所以它在 4.7 上一条都匹配不到（点了没反应）→ 才自研 bake。
- **`.tscn` 里不能写 `type="AutoTunable"`**：headless `Cannot get class 'AutoTunable'`，
  编辑器里 `Class "AutoTunable" hides a global script class`，节点退化 placeholder、面板 0 控件。
  改成 `type="Node"` + `script = ExtResource(...)` 指向 auto_tunable.gd，绕开全局类表。
- **AutoTunable._ready 时序**：节点进树时若 tuner 还不存在，该节点**永久放弃注册**。
  headless 探针必须先 `root.add_child(DebugTuner)` 再 `psc.instantiate()`。
- **正则两个坑**：属性名拼接必须用 `|`（写 `/` 会被当字面量 → 0 命中且不报错）；
  **命名组在 PCRE 里也占编号**，`get_string(2)` 对 `(?P<name>...)` 而言取到的是属性名不是值，
  所以数值捕获也要命名 `(?P<old>...)`。
- **SceneTree 的 `_process` 必须 `-> void`**（写 `-> bool` 报签名不匹配父类）；
  `Control.AUTOWrap` 不存在（换行枚举在 TextServer 下）；`Node` 静态类型下直接点 `node.max_speed`
  过不了静态检查，一律用 `node.get("max_speed")` / `node.set(prop, v)`。
- `current_scene` 只在正常加载场景时才有值（自己 `instantiate()+add_child` 是空的）→
  找目标先 `current_scene`、回退 `get_tree().root` 再 find_child。
- **跑整场景 headless（`--quit-after`）时偶发「退出码 1 + 输出文件都没建」**，
  `--script` 探针则稳定；验证 autoload 行为就自己 `load(script).new() + add_child()`。
  同一台机器上 bash 工具里的子进程 spawn 也会莫名 EBUSY，Godot 相关一律走 PS 工具。

### 踩坑清单（4.7，全部实测）
- **`find_children` 的 owned 默认 true，且是按 `owner` 属性过滤、不是按父子关系**。

## 「蜜蜂骑在车顶上」——根因是四台车 transform 完全重叠

- 现象：选「蜜蜂载具」进原版赛道，画面上蜜蜂像坐在黄色皮卡的**车顶**上。用户原话：「我只要蜜蜂啊」。
- **根因：`scenes/main.tscn` 里 `Vehicle` / `Vehicle2` / `Vehicle3` / `Vehicle4` 四台载具的
  `transform` 一模一样都是 `(3.5, 0, 5)` —— 四台**完全重叠**在同一个出生点。**
  玩家那台被 picker 换成蜜蜂后，新 `Model` 是 `Container` 最后 `add_child` 进来的，
  渲染顺序排在最后 = 画在最上层，于是蜜蜂盖在三台静止黄皮卡上 ⇒ 看着像骑在车顶。
- **蜜蜂本身没有浮空**：`model_origin_y=-0.584`、`Model.scale.y=0.056`、`Container.y=0.434`
  ⇒ 模型底面 `0.434 + (-0.434) = 0`，正好贴地。
  ⚠️ 探针输出里那个「世界底面y = -0.5」是**探针公式把 0.65 减了两遍**造成的假象
  （`model.position.y` 已经是脚本每帧写好的值，不能再额外减一次 0.65），别拿它当结论。

## 四台车同步跑的修复（is_player）

- 现象：选了蜜蜂进原版赛道后，画面里**所有黄车一起跟着玩家走**。探针 Temp/who_moves2.gd 量出 Vehicle / Vehicle2 / Vehicle3 / Vehicle4 四台 Sphere 位移**一模一样**（1.06 / 7.58 / 16.58，脚本速度 8.26 / 9.75 完全相同），而装饰车 vehicle-truck-green / purple / red 各 4 台位移恒 0。
- 根因：scenes/main.tscn 里四台车都是同一个 scenes/vehicle.tscn 实例（同一个 ExtResource 7_o6xl0），全挂 vehicle.gd，而 handle_input() 读的是**全局 Input** —— 脚本里没有「谁是玩家」的概念，一踩油门四台同步开。
- **探针观测点陷阱（重要）**：Vehicle 这个 Node3D 自己**永远不动**（vehicle.gd 只写 Sphere.position 和 Container.position），所以拿 veh.global_position 量位移恒为 0，会得出「没人动」的假结论。必须量 **Sphere（RigidBody3D）** 的 global_position / linear_velocity。第一版探针 Temp/who_moves.gd 就是栽在这上面，白跑一轮。
- 修法：scripts/vehicles/vehicle.gd 加 @export_group(操控归属) + @export var is_player: bool = false；handle_input() 里「if is_player 读 Input，否则 input.x / input.z 归零后 return」；_physics_process 里非玩家车把 linear_velocity.x / .z 钉 0（GridMap 的 PhysicsMaterial friction=0，不钉的话被撞一下会沿路面一路滑走，看着还是黄车自己跑）。
- scenes/main.tscn：[node name=Vehicle] 下加一行 is_player = true（实例节点写脚本属性，只影响这一台）；Vehicle2 / 3 / 4 从 x=1.4 / -0.9 / -3.2 挪到 **x=-5.5 / -9.0 / -12.0**（z=3 / 5 / 7 错开）= 摆到左侧路肩当静止装饰，起步线正前方全空。
- 复验：Temp/who_moves2.gd 再跑一遍，只有 Vehicle 有位移（1.06 / 7.58 / 16.23），Vehicle2/3/4 三段快照全是 0.0。目视图 Temp/orig_bee.png：蜜蜂居中、前路全露，左边只有树，黄车已出画。
- 注意：**Edit 工具会把文件写成纯 LF** —— 改完 vehicle.gd 要马上 node 归一回 CRLF（542 行全 CRLF）。项目源文件必须 CRLF。用 node 写日志时**别在 shell 命令里写反引号**，bash 会当命令替换把内容吞掉（本轮踩过，日志里全是空白）。
