# 洛圣都计划（Los Santos Plan）—— GTA 式开放世界底座 + 五玩法缝合 / 多人联机 总设计文档

> 本文件是本项目**唯一总纲**，取代 `DESIGN_road_rash.md` 的顶层定位
> （后者保留为「载具缠斗子系统」的区间规格，见文末 §9）。
>
> 一句话定义（v3，2026-10-04，五玩法需求进来后改的）：
> **一张 Kenney 画风的都市沙盒：白天开车挣钱、种地盖房、整理旧书换图纸；天一黑尸潮来守家；
> 周末跑街道赛，攒够零件就上塔。GTA 提供底座（车 / 城 / 钱 / 昼夜 / 联机房间），
> 五种玩法是长在底座上、可各自开关的模块，靠同一条时间轴和同一套资源咬成一种日子。**
>
> 主干没变：**自由行驶 + 多人联机永远是地面**（v1 定义，红线 R2/R6）；
> RTS 化阵营战争从「天花板」改为**待拍板的可选层**（§2.0.7 Q3）。
> 五玩法需求登记在 §0.6，缝合方案与排期在 §2.0 与 §4.5。

## 0. 设计红线（先钉死，后面所有讨论都按它判）

| # | 红线 | 原因 |
|---|---|---|
| R1 | **手感优先于拟真**。街机手感，不追求物理正确 | 现有自研 `Vehicle`（Node3D + RayCast 地轮 + 刚体球）已经是街机模型，不再推倒 |
| R2 | **先自由行驶，再 RTS**。RTS 指挥不能抢走开车的操作权 | 用户明确优先级：先自由行驶 + 多人联机 |
| R3 | **权威服务器**。客户端只报意图，不报结果 | 反作弊 + 阵营战需要可信胜负 |
| R4 | **模块化**：一切功能都是模块，模块可开关、可并行开发、可单独下线 | 用户要求「按模块化完善项目」 |
| R5 | **风格一致性**：所有素材走 Kenney 套件 + 现有 `Textures/colormap.png` 调色板，不新增自定义材质 | 防黑体检（P0 裸网格）必须 0 失败 |
| R6 | **存量可用**：`scenes/main.tscn` 的随机赛道生成器、自研车辆、贴身相机、小地图必须继续能跑 | 不能为了新目标把老成果推平 |

## 0.5 需求更新 v2（2026-10-03 用户拍板，优先级最高）

## 0.6 需求更新 v3（2026-10-04 用户提出，本节是「五玩法缝合」的总入口）

> 用户原话：**以侠盗猎车 GTA 为底，有单机/联机，融合 ① 赛车 ② 吸血鬼幸存者 ③ 整理图书
> ④ 种田+建造 ⑤ 爬塔闯关 等各种玩法。**
>
> 一句话：**GTA 是「底座」而不是「玩法」**——都市、开车、上下车、金币、昼夜、联机房间是底座；
> 五种玩法是长在底座上的五个模块。它们不靠剧情硬讲，靠**同一条时间轴 + 同一套钱/材料/声望**咬合。
> 详细缝合方式与方案对比见 **§2.0**（这一节只登记需求与落点）。

| # | 需求 | 落进本设计的哪一层 | 现成度（本机实测，不是设想） |
|---|---|---|---|
| N8 | **单机 + 联机双形态** | 不新增层，是**所有层的约束**：每玩法都要有 SOLO 与 COOP 两条路径（§3.4 四房型已有骨架） | 底座已通：P2P host 权威 + 20Hz 快照（#10/#11），夜潮任务已验证 host/client 双端同步 |
| N9 | **赛车玩法** | **L1 的竞技化**：urban 街道赛（点对点）+ 老图闭环赛道（计时/多圈） | 车已有三档手动 + 速度 HUD（#31，满速 115 km/h）；`scenes/main.tscn` 随机闭环赛道生成器现成；**缺**：对手 AI、发车格、圈数判定、奖励结算 |
| N10 | **吸血鬼幸存者玩法** | **L5 夜潮 + 肉鸽成长层**：`#21 守夜讨伐` 已经是「夜里一波波涌来 + 站桩射击」，缺的正是幸存者那层**自动攻击 / 经验珠 / 升级三选一** | 波次导演、僵尸 GLB、枪械近战、攻击动画全有；**缺**：XP 与掉落、被动池、一局一清盘的 roguelite 结构 |
| N11 | **整理图书玩法** | 新增 **L6 室内整理层**（cozy / 委托式）：把搜刮来的书、档案、旧物按规则归类上架，按**评分**给钱 | 0。**功能钩子（关键设计）**：整理产出的不是钱，是**知识**——图纸（喂 L4 建造）、路况（喂 L1 赛车）、楼层情报（喂 L7 塔）。这是它不变成孤立小游戏的原因，范式见 §2.0.3 方案卡里的 Moonlighter |
| N12 | **种田 + 建造玩法** | N3 + N4 正式落地（此前只立项未动代码） | 地块现成：#29 小区（`scenes/suburb.tscn`，28 碰撞体 + 院落）就是天然载体；**缺**：放置/拆除、土壤与生长 tick、 watering、收获进 `modules/economy` |
| N13 | **爬塔闯关玩法** | 新增 **L7 塔层**：房间制 roguelite，一局一层，下来后把稀有图纸/零件在都市花掉 | 0；技术上无新轮子（Navigation、区块流式、任务框架、InteractionGate 全可复用） |
| N14 | **五玩法可各自开关** | 沿用红线 **R4 模块化**：一玩法一目录 `modules/<name>/` + 一张 `.tres` 声明，可下线不炸图 | 骨架现成（`modules/missions/` 已是这个形态：taxi / cargo / defense 三个任务共用 `mission_base`） |

**优先级与红线冲突，先摆出来**（详见 §2.0.7 待拍板）：
① 原总纲把 **RTS 化阵营战争（L3 / M4）** 当天花板，现在五玩法来抢同一份工时；
② 红线 **R2「先自由行驶，再 RTS」** 与 **R6「存量可用」** 仍然有效——任何缝合不能把「在都市里开车」降级成菜单；
③ 单人开发同时推五玩法 = 必然全是半成品，所以 §4.5 排的是**串行**，一次只把一个玩法做到「好玩阈值」。


## 1. 业界调研（动手前先找轮子）

### 1.1 GTA V 单机：开放世界靠什么成立

查证 Rockstar 开发访谈（Wikipedia / Justapedia 的 *Development of GTA V* 条目）：

| 事实 | 对我们的取值 |
|---|---|
| 地图 49 平方英里（≈130 km²），「大而不空」是明确设计目标 | 我们不做 130 km²，做 **4 km × 4 km = 16 km²** 的密集区（城市 60% + 郊野 40%），密度 > 面积 |
| 用 RAGE 重写渲染管线换 draw distance 到 ~2 km | 我们用 Godot 的 LOD + 雾 + 区块剔除，目标同款观感 |
| 三主角切换解决「跑长途回任务点」的空洞感 | 我们做「**一人多身份**」：单人开车，第三人称可下车的 NPC 小队（正好是 RTS 的抓手） |
| 动态任务（Dynamic Missions）：路上偶遇装甲车劫货，可接可不接 | 做 **随机事件系统**：路上刷抢车/劫店/直升机追捕，30 秒内能加入 |
| 射击去掉 hard lock，改为锁定时限 | 载具缠斗同理：锁定目标 3 秒自动脱锁，避免「按住开火」 |

### 1.2 GTA Online：多人层的四大骨架

查证 GTA Online 资料（Fandom / Rockstar 官网 / 第三方综述）：

1. **会话分层**：Solo / Invite Only / Crew Only / Public（默认）四种房型；数量 16→30 人。
   → 我们照抄四房型，上限先 8 人（局域网/单机作证），留 `MAX_PLAYERS` 常量。
2. **自由漫游（Free Roam）+ 独立副本**：跑图、劫车、帮派突袭、即时赛车都在同一个 30 人房间；
   而 Deathmatch / Race / Contact Mission 是**临时切走的独立局**（不共享世界）。
   → 我们的「RTS 战役」也是独立局（切场景），「抢车/街头火并」保持 Free Roam。
3. **CEO / 组织**：买办公室 → 注册 CEO → 雇保镖/副手 → 特种货物/载具货物/地堡/机库/夜总会 → 进货出货循环。
   **保镖每 10 分钟发薪 $10000，老板每死一次扣 $250**，这个「薪资契约」是 RTS 单位经济的最佳模板。
   → 我们叫 **势力（Faction）/ 小队（Squad）/ 单位（Unit）**，保镖改成可雇佣的 NPC 步兵与护卫车。
4. **帮派领地战 + 毒战（Drug Wars）**：三方对抗（卖方 / 执法 / 买方）、倒计时内把货卖完、
   路上刷抢货事件、据点（The Freakshop 之类）当 HQ。
   → 这就是用户要的「指挥警察打强盗、指挥军队打毒贩」的官方原型，**直接对齐**。

### 1.3 Godot 侧：成熟方案查询结论

查证 Godot 4 高层多人 API 与开放世界流式加载：

| 方案 | 结论 |
|---|---|
| Godot 4 高层网络（ENetMultiplayerPeer + MultiplayerSpawner + MultiplayerSynchronizer + @rpc） | **采用**，官方自带、够用。铁律：server 权威、每个玩家节点 `set_multiplayer_authority(peer_id)`、位置类走 `unreliable_ordered`、事件类走 `reliable` |
| 回滚（rollback）网络 | **不用**。Godot 自带不含 rollback，要挂第三方 addon；我们是街机赛车，客户端预测 + 服务器校正足够 |
| Terrain3D / ProtonScatter / OWDB（开放世界三件套插件） | ~~**暂不引入**~~（2026-10-03 v2 修订：**大地图改用 Terrain3D**，用户拍板，见 §0.5 N5；下列原因存档备查）原因：① 现有赛道是 GridMap 手工/生成砖块，风格锁定 Kenney；② 三件套同场景编辑会互相打架（社区实测编辑器花屏）；③ 16 km² 用自研区块流式 + 现有 tile 足够。列为 **M5 备选**：真要做山岭地形再引入 |
| 自研区块流式（chunk grid + 优先级队列 + 对象池 + 距离 LOD） | **采用**，约 200 行，完全可控 |

> **调研结论（明说）**：RTS 化阵营指挥在 Godot 上**没有成熟开源成品**可抄，
> 业界可抄的只有「GTA Online 的 CEO/毒战设计」+「经典 RTS 的单位/命令/资源三角」，
> 所以这一层是本项目的自研重点。

## 2. 玩法设计

### 2.0 五玩法缝合：这将会是一个什么游戏（v3，2026-10-04）

#### 2.0.1 三句话定位

| 视角 | 一句话 |
|---|---|
| **玩家会怎么说** | 「一个卡通风的美国城市：我买了院子，白天种地、开车送货、在屋里整理旧书换图纸；天一黑僵尸从街上来，我守着自己盖的墙打一波；周末去跑街道赛，攒够零件就去爬那座塔。」 |
| **设计上它在干什么** | 把「**生活循环**（挣钱→扩建→再挣钱）」和「**战斗循环**（威胁→防守→掉稀有物）」用**同一条昼夜时间轴**焊在一起，再用**同一套钱/材料/声望**当通用货币；赛车与爬塔是这两条循环的**周期性变现出口**（比赛日 / 上塔日）。 |
| **开发上它是什么** | 一个底座（都市 + 车 + 人 + 金币 + 昼夜 + 联机房间）+ **五个可开关的玩法模块**。底座已经交付完（#1~#32），五玩法各自 1 个 `modules/<name>/`，互不引用，只经 `core/event_bus` 与 `modules/economy` 说话。 |

**它不是什么**（同样重要，防跑偏）：
- 不是「GTA 同人」——没有枪战主线、没有犯罪声望，GTA 只借它的**开放世界骨架**（自由开车 + 差事 + 通缉）。
- 不是「5 个小游戏合集」——合集的判据是**玩法之间没有资源流动**；我们的硬指标是：任何一个玩法停摆，另外四个都会缺料。
- 不是「RTS 阵营战」——那一层（L3/M4）仍在设计里，但**它不再是天花板，而是待拍板的可选项**（§2.0.7 Q3）。

#### 2.0.2 缝合方式：四套方案卡

> 每套按 AGENTS.md §3.1 的七个字段写。结论在 §2.0.3。

##### 方案 A｜Hub + 副本（GTA Online 式）

| 字段 | 内容 |
|---|---|
| 核心理念 | 都市是永远在的「家」，五玩法各是一扇门/一张接单牌：进去打一局、出来结算，世界不共享 |
| 适用 / 不适用 | 适：玩法差异极大（赛车和整理图书根本不是一个引擎）、要并行开发、要开房间联机。不适：想让「我的世界」有连续感 |
| 核心机制 | 场景切换 + 局实例：`urban.tscn` 常驻，玩法各自一张 `.tscn`，进局换场景、结算写回存档与钱包 |
| 优点 | 每种玩法能做深、能做独立手感；一个玩法炸了不影响其他；联机天然（房主开局、邀请进人）；工时可控 |
| 缺点与代价 | 都市会**空**——只剩一张菜单；玩法之间共享的东西太少，五张皮一张底，玩家没有「我在过同一种日子」的感觉 |
| 代表作品 | GTA Online（自由漫游 + Adversary/赛车/差事独立局）、FF14（主城 + 副本）、Destiny 2（塔 + 打击/突入） |
| 关键取舍 + 已知坑 | 取舍：连续感换开发效率。坑① 换场景会销毁网络节点——`net/session.gd` 必须常驻 autoload，否则客机进一次副本就掉线；坑② 局外状态（材料/图纸）要能**污染** hub（盖墙、买车），否则循环闭不上 |

##### 方案 B｜一张世界 + 昼夜周历（生存沙盒式）

| 字段 | 内容 |
|---|---|
| 核心理念 | 所有玩法发生在同一张图、同一条时间轴上：白天种地/整理/送货，夜里尸潮守家，周末比赛，塔立在城边 |
| 适用 / 不适用 | 适：想要「我这块地盘」的沉浸感、玩法靠**日程**互相咬合。不适：想要每种玩法都有独立竞技规则（尤其赛车要赛道封闭性） |
| 核心机制 | 一个世界时钟（host 权威）驱动阶段：`DAY → DUSK → WAVE → DAWN`，周历再叠一层（周末开赛事、月末开塔）。#21 的 `_phase` 状态机就是它的雏形 |
| 优点 | 唯一一条时间轴天然把五玩法缝死（今天砍的柴 = 今晚守的墙）；已有代码复用度最高（昼夜、波次、金币、小区地块全现成）；玩家永远知道「现在该干什么」 |
| 缺点与代价 | 玩法互相牵制（赛车要在开放世界里封路、爬塔要在图里造一座塔）；时间推进要仲裁，客机断线时世界时间不能停；节奏不好调（种田 8 分钟被夜潮打断就是灾难） |
| 代表作品 | Palworld（基地 + 昼夜威胁 + 采集）、7 Days to Die（白天搜刮夜里守家）、Core Keeper、Stardew Valley（季节时钟） |
| 关键取舍 + 已知坑 | 取舍：开发效率换沉浸感。坑① **离线补算**——生长 tick 必须按时间戳结算，不能按帧数，否则玩家下线三天回来作物没长；坑② 世界时钟改 `#21` 的 `_phase` 语义，会连带影响夜潮触发点，改前必须先跑 `Temp/v21_probe.gd` 回归 |

##### 方案 C｜Roguelite 元推进（Hades / Moonlighter 式）

| 字段 | 内容 |
|---|---|
| 核心理念 | 塔是主循环，上楼 = 一局；下楼把收获花在都市（扩建、开店、买车），花完再上楼 |
| 适用 / 不适用 | 适：单人、重玩性、进度曲线清晰。不适：联机（塔内天然各打各的，要共局得做房间实例）、以及任何「我就想开车逛街」的诉求 |
| 核心机制 | 双层循环：局内（房间→房间→Boss，死亡清空）+ 局外（都市永久升级），中间用「图纸/零件」当唯一出口 |
| 优点 | 最好玩的那一类结构（每局都不一样）；美术成本最低（房间可以复用同一套 Kenney 件）；「整理图书」在这里最自然——它就是局外经营层 |
| 缺点与代价 | **直接撞红线 R2**：GTA 的自由行驶被降格成大厅，都市不再是主体；联机最弱；一局的平衡要反复调，工时花在数值上 |
| 代表作品 | Hades（家宅永久升级 + 每次出逃一局）、Moonlighter（白天开店整理货架、晚上打地牢）、Dead Cells |
| 关键取舍 + 已知坑 | 取舍：主干自由感换局内深度。坑：如果保留都市自由行驶，就必须处理「局内受伤/死亡 → 局外车还停在城里」的状态对账，很容易做出「人死了车还在街上跑」的 bug |

##### 方案 D｜如龙式任务集（玩法 = 差事类型）

| 字段 | 内容 |
|---|---|
| 核心理念 | 一切以「谁给你活干」组织：告示板 / 电话 / NPC 派发，五玩法就是五类差事，靠剧情与声望推进 |
| 适用 / 不适用 | 适：玩家不知道干什么的时候永远有人派活；文案能把不相干玩法讲圆。不适：单人开发做海量任务脚本 |
| 核心机制 | 任务表（数据驱动 `.tres`）+ 派发点（`InteractionGate` 已就位）+ 结算（`modules/economy` 已就位） |
| 优点 | 最贴 GTA 底座；上手成本最低（照 #21 的告示板抄，五玩法 = 五个告示板）；进度、解锁、引导全在任务层解决 |
| 缺点与代价 | 内容量爆炸：每类差事都要独立脚本、独立 UI、独立结算文案；**小游戏感最强**（如龙系列本身就被批评「主线 + 一堆不相干小游戏」）；玩法之间依然没有资源流动，容易做成合集 |
| 代表作品 | 如龙 / Like a Dragon 系列（黑道主线 + 经营/街机/钓鱼一堆支线）、Sleeping Dogs、GTA V 的 Contact Mission |
| 关键取舍 + 已知坑 | 取舍：讲圆故事换内容工时。坑：任务脚本复用度低，单人开发最容易死在「第 40 个差事」上——所以 D 只能当**语言**（怎么派活、怎么说话），不能当**骨架** |

#### 2.0.3 结论：B 当骨架 + A 当副本外壳 + D 当语言 + C 只用在塔里

**推荐组合（一句话）**：用 **B** 的那条昼夜/周历时间轴把五玩法焊成一种日子；玩法内部需要封闭规则的两类（赛车、爬塔）按 **A** 做成**局实例**（进局换场景、结算写回）；派活与提示文案全按 **D** 走现成的告示板 + `InteractionGate`；**C** 的双层循环只用于塔（局内一局一清、局外永久升级）。

| 方案 | 在组合里的角色 | 为什么不单选它 |
|---|---|---|
| B | **骨架**：世界时钟、周历、地盘感 | 单用会让赛车/爬塔被迫塞进开放世界，规则做不干净 |
| A | **外壳**：赛车局、塔局、夜潮局三种局实例 | 单用会把都市做成菜单，丢掉 GTA 底座（撞 R2） |
| D | **语言**：所有入口都是「一张单子 + 一个 E 键」，复用 #21 形态 | 单用 = 小游戏合集（玩法间无资源流动） |
| C | **塔的内核**：房间推进 + 局外图纸升级 | 单用 = 撞 R2，且联机最弱 |

**为什么不选「纯 A」或「纯 C」**：它们都会把已经交付完的底座（#1~#32：都市、开车、上下车、金币、昼夜、联机、小区、天空）浪费掉；B 是**唯一一条几乎不改底座**就能长出来的路线。

#### 2.0.4 统一循环（这游戏的心跳）

```
      ┌──────────── 白天 DAY ────────────┐
      │ 种地/收获 · 送货/出租 · 整理图书→图纸 │   ← 挣「钱 + 材料 + 知识」
      └───────────────┬───────────────────┘
                      │ 傍晚 DUSK：交付、结账、把图纸花掉（盖墙/扩建/买车/改装）
      ┌───────────────▼───────────────────┐
      │ 夜里 WAVE：尸潮来守家（幸存者那层肉）│   ← 消耗白天的一切，掉「稀有零件」
      └───────────────┬───────────────────┘
                      │ 天亮 DAWN：结算 + 世界时钟推进一天
      ┌───────────────▼───────────────────┐
      │ 周末 = 街道赛（钱×2 + 名声）        │   ← 变现出口 1
      │ 攒够零件 = 上塔（一局一层，掉图纸）  │   ← 变现出口 2 → 回到白天能盖更大的
      └───────────────────────────────────┘
```

**闭环判据（做完要能对得上）**：塔里的图纸 → 能盖更大的院子 → 能种更多 → 夜潮守得住 → 守得住才有钱买车 → 车够好才赢街道赛 → 赢了才有零件上塔。**环上任何一环断开，就说明那个玩法做成了孤岛。**

#### 2.0.5 五玩法设计卡

| 玩法 | 一局多长 / 核心循环 | 结算与奖励 | 单机 vs 联机 | 复用现成 | 最大风险 |
|---|---|---|---|---|---|
| **赛车**（N9） | 3~6 分钟：接单 → 封路发车 → 3 圈/点对点 → 冲线 | 名次给钱 + 圈速纪录给名声；车损照扣 | SOLO：3 个 AI 对手。COOP：真人 + AI 补位，host 判名次 | 三档车（#31）、随机赛道（`mapgen.gd`）、urban 路网、金币（`modules/economy`） | **对手 AI 是全新代码**，且 Kenney 车没有碰撞箱分级，AI 撞墙会炸手感；先做「计时赛 + 幽灵回放」比做 AI 便宜一半 |
| **吸血鬼幸存者**（N10） | 10~15 分钟一夜：怪一波比一波大 → 吃经验珠 → 升级三选一 → 天亮清盘 | 稀有零件 + 波次金币（#21 已有） | SOLO 已有。COOP：同图共享 XP 还是各自一套，**必须先定**（默认：共享怪、各自 XP） | #21 全套（波次导演、僵尸、枪械、攻击动画、HUD 行） | 只加「自动攻击 + XP + 三选一」三层，容易做成**没有 Build 差异的刷怪**；升级池要一次给够 12 个以上才有肉鸽味 |
| **整理图书**（N11） | 5~10 分钟一单：按委托人规则归类上架 → 评分（速度/正确率/美观） | **主要产出是知识**：图纸（喂建造）、路况（喂赛车）、楼层情报（喂塔）；钱是次要 | SOLO 单人整理。COOP：一人理一层 / 分工（一人分类一人上架），做成**协作休闲局** | 小区室内地块（#29 有院子、屋里待拍板）、`InteractionGate`、物品拖拽可抄 Unpacking 范式 | 最容易被当成「凑数玩法」。**必须绑死知识产出**，否则玩家没有理由碰它；另外它需要**室内空间**——「进屋」这条待拍板项是它的前置 |
| **种田 + 建造**（N12） | 以「天」为单位：翻土播种 → 浇水 → 长（按时间戳补算）→ 收 → 卖/吃；建造 = 放件花材料 | 作物进 `modules/economy`；建筑进世界快照（存档） | SOLO 自己的院子。COOP：**共地还是分地**必须先定（默认：同一院子共享墙与作物，避免两套同步） | 小区套件（`models/suburban/` + `scenes/suburb.tscn`）、city-kit 件当建造套件、昼夜（#21/#32） | 生长 tick 与联机权威重叠 → 客机看到的作物和 host 不一致；**放件系统要能撤销**，否则误放一堆墙把夜潮路堵死就是自伤 |
| **爬塔**（N13） | 15~25 分钟一局：一层 = 3~5 个房间（战斗/事件/商人/宝箱）→ 层 Boss → 死则清盘 | 图纸与稀有零件（局外永久），层数给名声 | SOLO 主推。COOP：同层共局（推荐，2~4 人）或各打各的比层数 | 房间 = 复用 Kenney 件 + 区块流式；怪复用 #21 僵尸 + 墓园包；`Navigation` 现成 | **内容量最大**（每层要有变化），且它和夜潮抢同一套怪 → 不做敌人变体就会「上下都是那几只」 |

#### 2.0.6 防「缝合怪」的三条纪律（写死，评审时逐条判）

1. **资源单向流动检查**：新玩法上线前必须回答「它消耗什么、它产出什么、下游是谁」。
   答不出下游 = 孤岛 = 不许开工。（例：整理图书的下游是建造图纸与塔层情报。）
2. **一次只做一个玩法到好玩阈值**（AGENTS.md §5「不做半成品」的玩法版）：
   串行推进（§4.5），禁止五个玩法各铺 30%。
3. **底座不可侵犯**：任何玩法不得让「在 urban 里自由开车 + 上下车」变慢或变绕
   （R2/R6）。具体判据：进任何一局的时间 ≤ 3 秒、下车点永远可达、`urban.tscn` 主干不因为玩法模块关闭而报错。

**设计纪律**：L1 永远是底，L2 只在接触时发生，L3 只在玩家主动进战术视角时发生。
绝不能出现「一按 RTS 键就开不了车」这种把主干打断的做法。
**v3 追加**：L4~L7 一律**不得改 L1 的操作权**——进任何一局的方式必须是「走到门口按 E」，
不是「弹菜单把世界换掉」（判据见 §2.0.6 第 3 条）。

|---|---|---|---|---|

#### 2.4.3 战术视角（Command View）

- 触发：玩家**下车站在地面**并按 **F5**，或载具被摧毁后。开车时禁用（保 R1）。
- 相机：从玩家后上方拉到 **45° 斜俯视，`height=28 / distance=34`**，沿用 `scripts/view.gd` 的插值逻辑，只是目标距离换成战术值。
- 时间：默认**实时**；按住 **Shift = 0.35 倍慢动作**（这是 RTS 指挥爽点，且实现只需 `Engine.time_scale`）。
- 输入：
  - 左键点地面 → `MOVE`（寻路过去）
  - 左键点单位 → 选中；Ctrl+左键 → 加选
  - 左键点敌人 + 选中单位 → `ATTACK`
  - **B** → `FLANK`（绕后，AI 自选侧翼路点）
  - **H** → `HOLD`（原地守，遇敌交火但不追）
  - **E** → `ESCORT`（护送当前玩家角色）
  - **Q** → 呼叫支援（武装直升机 / 空袭 / 医疗包），有冷却 + 威望消耗
  - **Tab** → 单位面板（选中小队血条/弹药/命令队列）
- 退出：**F5 / Esc** 回到第三人称。

#### 2.4.4 单位与命令（自研，无成熟成品可抄）

```
Unit（单位）= 一个 Node3D + UnitState
   kind:     INFANTRY | BIKE | CAR | TANK | BOAT | HELI
   faction:  GANG_A | GANG_B | POLICE | MILITIA | CARTEL | PLAYER
   hp / ammo / stamina / morale / stun
   orders:   Array[Order]        # 命令队列，先进先出
   ai:       状态机 IDLE→MOVE→ATTACK→SUPPRESS→FLANK→RETREAT→DEAD

Order（命令）= 纯数据
   { type, target_id, waypoint, ttl }   # 不存引用，只存 id（跨网络可序列化）
```

**关键设计（防坑）**：
1. **命令必须是纯数据**（只放 id 和坐标），绝不存 Node 引用——否则一断线就崩，且没法跨端同步。
2. **单位不做高频网络同步**：RTS 单位只在**本地可视半径内**跑视觉插值；战斗结果由服务器批量下发事件（`deaths` / `damage` / `captures`）。10~30 台单位 × 60Hz 同步必炸带宽。
3. **服务器跑真实模拟，客户端只跑表现**：`Unit` 的 AI 在服务器跑，客户端收到的是「单位在哪 + 它现在在哪个状态」的低频快照（10Hz）。
4. **胜负只认服务器**：`FactionManager.resolve()` 判定，结果用一次 `reliable` RPC 广播。

#### 2.4.5 RTS 与自由行驶的耦合（这是能不能好玩的分水岭）

| 耦合点 | 设计 |
|---|---|
| **上车 = 取消指挥** | 玩家一上车，小队自动切 `ESCORT`（跟车），不再显示战术界面 |
| **单位只有「在附近」才激活** | 战术距离 160 m 内的小队跑 AI，远处的挂起（省 CPU，也省同步） |
| **自己也能是单位** | 玩家角色本身是一个 `unit_id`，可以「把自己编入小队」，于是 RTS 与第三人称无缝 |
| **载具也能下令** | 坐在车里按 F5 → 进入「车长视角」：只能给 **ESCORT / 呼叫支援 / 原地掩护** 三种命令（因为手在开车） |

### 3.3 模块注册表（M0 要落的代码契约）

```gdscript
# scripts/core/modules.gd（autoload: Modules）
# 每个模块在 data/modules/<name>.tres 里声明 name/deps/enabled
# 启动时：按依赖拓扑排序 → 依次 instantiate → add_child → 调 module._enter_module()
# 支持 mid-game 热插拔（rooms 切换、战役载入）
```

**模块铁律**：
1. 任何模块不得直接 `get_tree().get_nodes_in_group()` 抓别人的节点——只通过 `EventBus` 或显式接口。
2. 模块 `MTARGET` 版本号写死在 `mod.cfg`，靠它判断存档兼容性。
3. 单模块崩溃要能隔离：`ModuleRegistry` 捕获 `error` 后 `disable(module)` 而不是拖垮整个游戏。

### 3.4 网络层（M0）

```
                 ┌────────────── SERVER（authority）──────────────┐
  client input ──▶ reliable RPC（每 20~30 Hz 打包一次输入帧）      │
                 │  校验：速度上限、穿墙检测、单位归属              │
                 │  模拟 → 生成快照                                │
                 └─────────────┬────────────────────────────────┘
                               │ unreliable_ordered 20Hz（位置/朝向/fov）
                               │ reliable（事件：命中、爆炸、占点、任务阶段）
                               ▼
                         client 插值 + 外推（最多 100ms）
```

**通道与频率**：

| 数据 | 通道 | 频率 | 谁产生 |
|---|---|---|---|
| 玩家输入 | reliable RPC（批量） | 20 Hz | client |
| 玩家/载具位姿 | unreliable_ordered | 20 Hz | server 快照 |
| 相机 | 本地自建（不同步） | 60 Hz | client |
| NPC/单位位姿 | unreliable_ordered | 10 Hz（RTS 单位） | server |
| 命中/爆炸/占点 | reliable | 事件驱动 | server |
| 通缉星级变化 | reliable | 事件驱动 | server |

**房型（抄 GTA Online）**：
```gdscript
enum RoomMode { SOLO, INVITE, CREW, PUBLIC }
# SOLO：建服 1 人；INVITE：只放邀请；CREW：只放同一势力；PUBLIC：混合
# GTA 铁律：SOLO 房也能看到 NPC 与随机事件，只是没人打你
```

**必守的四个坑**（Godot 高层网络实测）：
- `MultiplayerSpawner` **只同步「存在」和「初始状态」**，之后的属性同步必须挂 `MultiplayerSynchronizer`；载具这种连续量别指望它。
- 生成后必须 `set_multiplayer_authority(peer_id)`，否则本端输入静默失效。
- **所有端上 `@rpc` 签名必须完全一致**，Godot 会对整条脚本做 checksum，不一致是静默失败。
- 载具同步**别用整包 snapshot 全量覆盖**：现有 `Vehicle` 是「每帧覆写 `linear_velocity`」的控制器，远端一覆盖就直接闪回。做法是：客户端发输入，服务器跑同一个控制器（lockstep-ish），只同步最终位姿 + 少量漂移校正。

### 3.5 开放世界（M1）

- **尺寸**：4 km × 4 km；区块 `CHUNK = 128 m`，可视半径 4 格（512 m）+ 卸载余量 1 格。
- **加载**：`WorldStreamer` 每帧算出玩家所在格 → 距离权重排序 → 每帧最多实例化 2 个 chunk → 走对象池。
- **LOD**：>200 m 的静态网格换简化版（同 `.tres` 材质，低模），>500 m 直接关碰撞只留远景。
- **道路网（M2）**：现有 `mapgen.gd` 的「随机闭环 + 直道/弯道/finish/ramp」是**单圈赛道**，
  开放世界版要改成**路网图（graph）**：节点 + 边，边上生成直道/弯道 tile，节点生成路口。
  `generate_network(seed) -> {nodes, edges, lanes}` 仍是纯函数，方便离线校验。
- **导航（M3 RTS 要）**：Godot `NavigationAgent3D` 给载具/步兵；RTS 层用**粗网格 A***（64 m 一格）跑 squad 寻路，别让 30 个 agent 各跑各的。

### 3.7 势力 RTS 内核（M3，自研）

```
FactionManager (server)
 ├─ Faction[]            # GANG_A / GANG_B / POLICE / MILITIA / CARTEL
 │   └─ Squad[]          # 3~5 Unit
 │       └─ Unit         # 纯数据 + 视觉 Node（客户端）
 ├─ OrderQueue           # 命令队列，纯数据 {type, target_id, waypoint, ttl}
 ├─ ResolveTick          # 每秒结算：占点、减员、薪资、胜负
 └─ EventOut             # 批量下发事件
```

- **单位状态机**：`IDLE / MOVE / ATTACK / SUPPRESS / FLANK / RETREAT / DEAD`
- **战术行为（让 RTS 不是傻冲）**：
  - `FLANK`：以目标为圆心，按自己所在方位挑「背离目标正面 60°~120°」的路点走。
  - `SUPPRESS`：停在 45~70 m 处持续低伤害压制，降低目标命中率（参考 GTA 的射击节奏）。
  - `ESCORT`：跟随指挥官，保持 8 m，遇敌先挡。
  - `RETREAT`：血量 < 25% 撤退到治疗点，用薪资资源回血。
- **呼叫支援**：`Q` 键 → 消耗威望 → 服务器 spawn 武装直升机（MOC/CEO 的空中支援移植），冷却 90 s。
- **薪资契约（抄 CEO）**：单位每秒扣「威望」，指挥官死亡扣全队（GTA 里是老板死扣钱），逼玩家别莽。

- GridMap 节点自带 **0.75 缩放**，真实格距 = `0.75 × cell_size`，手工按「格号 × cell_size」摆物会越远越偏。一律用 `GridMap.transform` 反算格中心（已在 `mapgen.place_cars` 修过）。
- `.tscn` 里**行尾 `#` 注释会吞掉后面所有节点**，注释必须独占一行。
- 4.7 无 `draw_rounded_rect`、`world_to_map`、`..` 区间语法；一律自查。
- 车出生高度 = 最终高度（每帧覆写速度），路面顶 y=0.75 时出生 y≈1.3。

## 6. 风险与权衡（明说）

| 风险 | 决策 |
|---|---|
| Godot 自带网络没有 rollback，高速撞车在 150 ms 下会穿模 | 接受：撞车用「命中判定走服务器 + 客户端解抖动位移」，不做 rollback；真要再上第三方 addon |
| 16 km² + 30 单位 RTS 在 Godot 上 CPU 吃紧 | 先做 8 人 / 每方 3 小队；`Unit` 用对象池 + 距离激活，远处挂起 |
| 开放世界要做掉现有「随机赛道」 | 不做替换：赛道保留为「赛道区」，开放世界为「城区」，两者共用一套 tile 与材质，靠区块流式拼起来 |
| RTS 抢走驾驶手感 | 战术视角开车时禁用（2.4.3）；永远保 L1 底 |
| Kenney 素材是方块低模，做不出 GTA 的城市场景密度 | 接受低模卡通风，反而和 colormap 调色板统一；用密度（层数 + 装饰）补面积 |
